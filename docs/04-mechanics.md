# 04. Движок механик и каталог клеток

## 1. Модель

### 1.1 Термины

- **Бросок** — трата кубика, генерация значения сервером, перемещение.
- **Событие** — срабатывание клетки, на которую встал игрок после броска.
- **Эффект** — состояние, которое висит на игроке и меняет будущие броски или поглощает чужие события.
- **Ожидание** — состояние, когда событие ждёт выбора игрока или второго участника.

### 1.2 Жёсткие правила движка

1. Событие срабатывает **только на конечной клетке перемещения от кубика**.
2. Дополнительные перемещения (Контратака, Голевая передача, VAR, Ответный матч, Последняя минута, Контракт) **не запускают** событие новой клетки. Цепочек нет.
3. Перемещение никогда не уводит ниже клетки 1 и выше 80. Клетка 80 — финиш: игрок получает `finished_at`, дальнейшие броски запрещены (`PLAYER_FINISHED`), кубики не сгорают и остаются в профиле. Первый дошедший — победитель сезона по дистанции, остальные продолжают борьбу за места (`DECISIONS D11`).
4. Итог броска сохраняется на сервере. Перезагрузка страницы не даёт нового значения и не отменяет выбор.
5. **Ожидание блокирует только следующее действие этого игрока.** Чужие ходы, ожидание второго участника и модерация админа игру не блокируют.
6. Смена правил клетки не влияет на уже начавшееся событие: оно завершается по `rule_version`, сохранённому в `cell_events`.
7. Щитки срабатывают автоматически. Добровольный риск (VAR, контракт, симуляция, джентльменское соглашение, проигранная мини-игра) Щитками не отменяется.
8. Повторное получение не складывается, кроме явно указанных случаев.

### 1.3 Порядок расчёта броска

```
value = dice.roll(sides)                       // только на сервере
value = value + tribuny_bonus(если есть)        // +1, расходует заряд
value = value + gazon_penalty(если есть)        // -1, расходует заряд
value = max(1, value)                           // минимальный шаг
если активна Тактическая схема:
    показать игроку value и дать выбрать -1 / 0 / +1
    value = clamp(value + выбор, 1, ...)
move(from, value)
```

Трибуны и Газон применяются **вместе** и оба расходуют заряд, даже если взаимно компенсировались.

### 1.4 Типы клеток

| Тип | Поведение |
|---|---|
| `plain` | «Обычная клетка. Без дополнительных условий.» Ничего не происходит |
| `instant` | эффект применяется сразу, без выбора |
| `choice` | игрок обязан выбрать, пока не выбрал — следующий бросок заблокирован |
| `partner` | ждёт ответа другого участника, **не блокирует** бросок |
| `moderated` | ждёт подтверждения админа, **не блокирует** бросок |

### 1.5 Схема эффекта

```ts
type EffectDef = {
  code: string;
  name: string;
  kind: 'movement' | 'buff' | 'debuff' | 'instant' | 'moderated';
  shieldable: boolean;        // отменяется Щитками при получении
  absorbable: boolean;        // поглощается Жёлтой карточкой
  stackable: boolean;
  duration: 'instant' | { rolls: number } | 'until_used';
};
```

## 2. Раскладка 80 клеток

- 1 — старт (`клетка 1`, без эффекта).
- 80 — финиш (`кубок`).
- 40 обычных (`plain`).
- 40 событийных (`event`), механики из каталога.
- Первые 5 клеток — обычные (плавный старт).
- Минимум 8 разных механик в первых 40 клетках.
- Две «жёсткие» клетки (Офсайд, VAR, Симуляция) не стоят подряд и не стоят на 2–4 клетках.
- Раскладка детерминирована `seasons.board_seed` (mulberry32). Одинакова для всех игроков, воспроизводима, проверяема тестом.
- Веса механик (на 40 событийных клеток), стартовые:

| Код | Механика | Вес |
|---|---|---|
| 01 | Контратака | 4 |
| 02 | Офсайд | 4 |
| 03 | Голевая передача | 3 |
| 04 | Скользкий газон | 4 |
| 05 | Домашние трибуны | 3 |
| 06 | Щитки | 3 |
| 07 | Раздевалка | 3 |
| 08 | Жёлтая карточка | 3 |
| 09 | VAR | 2 |
| 10 | Тактическая схема | 3 |
| 11–18 | вторая волна | по 2 после включения |

Веса и раскладка живут в `app_config.board` и правятся админом до старта сезона. Веса нормализуются к 40 клеткам методом наибольших остатков; ограничения проверяются после генерации, при нарушении сид инкрементируется (до 1000 попыток, детерминированно). См. `DECISIONS D12`.

## 3. Каталог 01–10 (обязательны к релизу 12 ноября)

### 01. Контратака
- Тип: `instant`, положительная.
- Эффект: `+3` клетки вперёд.
- Клетка после дополнительного перемещения не срабатывает.
- Визуал: ускорение персонажа, след, вспышка, звук `event-positive`.
- Тест: с клетки 10 → 13, событие 13 не запускается.

### 02. Офсайд
- Тип: `instant`, наказание.
- Эффект: `−2` клетки назад.
- Блокируется Щитками.
- Не уводит ниже 1.
- Клетка после отката не активируется.
- Уже выполненный откат Раздевалкой не отменяется.
- Визуал: флажок бокового судьи, свисток.

### 03. Голевая передача
- Тип: `choice`.
- Варианты: `Остаться на месте` / `Отдать передачу <участник>`.
- Выбранный получает `+1` клетку. Своё продвижение не даётся.
- Перемещение получателя не запускает его новое событие.
- Пока игрок не выбрал — его следующий бросок заблокирован.
- Ограничение «одна пара в день» — **по умолчанию выключено**, флаг в `app_config`. Если включён: пара (дающий, получатель) может сработать один раз за игровой день.
- Визуал: пас по дуге, получатель делает шаг.

### 04. Скользкий газон
- Тип: `debuff`, длительность 1 бросок.
- Эффект: следующий бросок от кубика `−1`, минимум 1.
- Повторное получение не превращает в `−2`.
- Щитки блокируют получение (но не лечат уже висящий).
- Снимается Раздевалкой.
- Визуал: скользящий бутс.

### 05. Домашние трибуны
- Тип: `buff`, длительность 2 броска.
- Эффект: `+1` к каждому из двух следующих бросков.
- Повторное получение восстанавливает заряд до 2, не суммируется.
- Может быть поглощено Жёлтой карточкой (если карточка уже висит).
- Визуал: шарфы, рёв трибун.

### 06. Щитки
- Тип: `buff`, `until_used`, 1 заряд.
- Автоматически отменяет одно подходящее негативное воздействие:
  - Офсайд;
  - получение Скользкого газона;
  - получение Жёлтой карточки.
- Не отменяет добровольный риск: VAR, контракт, симуляция, джентльменское соглашение, проигранную мини-игру.
- Повторное получение не создаёт бесконечный запас: `charges = 1`.
- Не снимает уже висящий негатив.
- Визуал: обязательный момент — показать, **что именно** предотвращено, затем значок исчезает.

### 07. Раздевалка
- Тип: `choice`.
- Если есть негативные эффекты — игрок выбирает, какой снять (Скользкий газон / Жёлтая карточка).
- Если негатива нет — запасной результат `+1` клетка.
- Не отменяет прошлые откаты, подписанные контракты, состоявшиеся проигрыши.

### 08. Жёлтая карточка
- Тип: `debuff`, `until_used`.
- Поглощает следующее получение положительного временного усиления: Домашние трибуны, Щитки, Тактическая схема.
- После поглощения карточка исчезает.
- Не отбирает кубики, мгновенное продвижение Контратаки, продвижение от Голевой передачи, заработанные награды.
- Если висит Щитки и приходит Жёлтая карточка — сначала срабатывают Щитки, карточка не появляется.
- Не выключает положительный эффект, полученный до неё.

### 09. VAR
- Тип: `choice`, добровольный риск. Щитками не блокируется.
- Варианты:
  - `Принять решение` → `−1` клетка.
  - `Оспорить через VAR` → 50%: `+3`, 50%: `−3`.
- Вероятности и последствия показываются **до** подтверждения.
- Случайность генерирует сервер, результат фиксируется. Перезагрузка не даёт новую попытку.
- Дополнительное перемещение не запускает новую клетку.
- Визуал: просмотр эпизода, решение судьи, звук `var-buzz`.

### 10. Тактическая схема
- Тип: `buff`, 1 бросок, `choice` после броска.
- Игрок видит выпавшее число и выбирает: `−1` / `оставить` / `+1`.
- Минимум 1 клетка.
- Это не переброс: значение уже сохранено.
- Повторное получение не накапливает коррекции.
- Пока выбор не сделан — бросок заблокирован.
- Поглощается Жёлтой карточкой.

## 4. Каталог 11–18 (вторая волна)

Все параметры — стартовый баланс, правятся в `app_config` без деплоя.

### 11. Тренировочная база
Одиночное испытание: 3 удара, выбор направления + остановка указателя силы. 2 попадания → `+2` клетки. Провал — без награды и без отката. Окно закрытия не даёт новую бесплатную попытку.

### 12. Узнай футболиста
Подсказки раскрываются по одной: позиция → страна → бывший клуб → текущая команда. Одна попытка ответа, неверный ответ завершает испытание. Награда зависит от числа открытых подсказок (3 → `+3`, 2 → `+2`, 1 → `+1`). Загадки готовятся админом и проверяются вручную, сравнение фамилии — нормализованное (регистр, ё/е, транслит).

### 13. Фан-сектор
Задание для компании на сайте или вне его: записать комментарий, придумать заголовок, сделать афишу, собрать сборную друзей, придумать кричалку. Выполнение подтверждает админ. У задания заранее есть условия, срок, критерий и награда. Награда выдаётся один раз. Минимум одно задание из пары — без обязательного видео или голоса.

### 14. Ответный матч
Вызов другого участника на серию пенальти: атакующий тайно выбирает направление удара, вратарь — прыжок, затем меняются. Победителю `+3`, проигравшему ничего. Вызов не блокирует игру. Отказ до начала не считается поражением. Ничья — по сумме, затем «внезапная смерть» до первого промаха.

### 15. Последняя минута
Push-your-luck: старт `+1`. Продолжить → 60%: `+3`, 40%: `0`. Ещё раз → 40%: `+5`, 60%: `0`. Можно остановиться и забрать текущее. Провал обнуляет только награду события, прошлые награды и кубики не отнимаются. Вероятности видны заранее.

### 16. Симуляция
Атакующий тайно выбирает «продолжить честно» или «нарисовать нарушение». Другой доброволец играет судью и выбирает «продолжить» или «проверить». Матрица:

| Атакующий | Судья | Итог |
|---|---|---|
| честно | не проверяет | атакующему +1 |
| симуляция | не проверяет | атакующему +3 |
| симуляция | проверяет | атакующему −2, судье +1 |
| честно | проверяет | атакующему +1, судье −1 |

Решения скрыты до фиксации обоих. Анимация не выдаёт симуляцию раньше ответа. Отказ или неответ не считаются поражением.

### 17. Контракт тренера
Добровольное обязательство на следующий игровой день: ответить минимум на 80% обычных вопросов и угадать не менее 2/3. Выполнил → `+4`, не выполнил → `−2`, отказался → ничего. Один активный контракт. Нельзя подписать на день с уже начавшимся матчем. Точные счета не учитываются, основной кубик считается независимо. Если после отмен осталось меньше 6 обычных вопросов — контракт аннулируется без последствий. Щитки не защищают.

### 18. Джентльменское соглашение
Психологическая дуэль. Оба добровольно соглашаются, затем тайно выбирают «сыграть командно» или «забрать себе».

| Решения | Итог |
|---|---|
| оба сотрудничают | каждому +2 |
| один забрал | ему +3, второму −1 |
| оба забрали | каждому −1 |

Решения не меняются после отправки и раскрываются только после фиксации обоих. Ожидание не блокирует движение. Щитки не отменяют. Ограничение «одна пара в день» — флаг в `app_config`, по умолчанию выключен.

## 5. Матрица взаимодействий

| Ситуация | Итог |
|---|---|
| Трибуны + Газон в одном броске | оба применяются и оба расходуют заряд; итог может быть 0 → минимум 1 |
| Щитки + приходит Офсайд | Щитки расходуются, Офсайд не применяется, показываем «предотвращено» |
| Щитки + уже висит Газон | Газон остаётся, защита не лечит |
| Щитки + приходит Жёлтая карточка | Щитки расходуются, карточка не появляется |
| Жёлтая карточка + приходит усиление | усиление поглощается, карточка исчезает |
| Жёлтая карточка + уже висят Трибуны | поддержка остаётся, карточка ждёт следующего усиления |
| Раздевалка | снимает один действующий негатив, прошлое не отменяет |
| Тактика | применяется после броска и всех модификаторов, до движения |
| Контратака / VAR / Голевая передача | конечная клетка не срабатывает |
| VAR + Щитки | Щитки не защищают |
| Ожидание второго участника | бросок ожидающего не блокируется |

## 6. Лента «комментатор»

Каждое действие пишет строку в `activity_log`:

| Событие | Текст |
|---|---|
| бросок | «Марк бросает золотой кубик: 6!» |
| движение | «Марк уходит на 6 клеток вперёд» |
| позитив | «Контратака! Марк проскакивает трёх защитников» |
| негатив | «Офсайд. Флажок поднят» |
| щитки | «Щитки спасают Марка от офсайда» |
| резолв дня | «День закрыт. Марк: 11 из 16, золотой кубик» |
| мини-игра | «Аня выигрывает серию пенальти 3:2» |

Лента живёт в правом нижнем углу карты, свёрнута в иконку, разворачивается по клику, не перекрывает карту и не мешает драгу. Показывать последние 30 событий, старые — по кнопке «Ещё».

## 7. Порядок разрешения события

```
1. Создать cell_events (state='pending', rule_version=текущая)
2. Проверить активные эффекты-поглотители:
     - Жёлтая карточка против положительного усиления
     - Щитки против shieldable отрицательного
3. Если эффект мгновенный — применить, state='resolved'
4. Если choice — создать pending_actions, state='awaiting_choice'
5. Если partner — state='awaiting_other', уведомить второго
6. Если moderated — state='awaiting_choice' для админа
7. Записать outcome + строку в activity_log
8. Обновить позиции и Realtime
```

Всё в одной транзакции. Если транзакция упала — состояние не меняется вообще.

**Если игрок не ответил:** `pending_actions.expires_at` = +24 часа. Cron `expire-pending` каждые 15 минут применяет безопасную ветку: VAR → «принять решение» (−1), Тактика → «оставить», Раздевалка → снять первый негатив (иначе +1), Голевая передача → «остаться на месте». В лог пишется «судья решил за него». Админ может разрешить ожидание вручную (`DECISIONS D7`).

## 8. Тесты движка (обязательные)

- `dice.test.ts`: границы тиров, ровно 1/3 и 2/3, Q=0, Q=1, Q=25, порог участия 0.79 / 0.80.
- `effects.test.ts`: Щитки против Офсайда, против Жёлтой; Жёлтая против Трибунов; Раздевалка без негатива → +1; повторный Газон не даёт −2.
- `movement.test.ts`: нет цепочек от +3, нет ухода ниже 1, финиш на 80.
- `board.test.ts`: раскладка по сиду воспроизводима, 40/40, первые 5 обычные.
- `idempotency.test.ts`: двойной бросок, двойной резолв, повторный выбор.
