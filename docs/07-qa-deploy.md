# 07. Тесты, деплой, запуск

## 1. Стратегия тестов

| Уровень | Инструмент | Что покрывает |
|---|---|---|
| Юнит | Vitest | `lib/game/*`, `lib/time.ts`, демо-снимок, нормализация провайдеров |
| Интеграция | Vitest + тестовая схема Supabase | RPC: бросок, резолв, идемпотентность |
| E2E | Playwright | вход, ответ на предикт, бросок, событие, админский резолв |
| Ручной | чеклист | визуал, звук, карта на разных экранах |

Минимальный порог покрытия ядра (`lib/game`, `lib/time`): **80%**.

Текущий срез: работают юнит-тесты (`npm run test:run`, 9 файлов, 163 теста). Интеграционные и Playwright-сценарии ждут подключения Supabase — до этого их запускать не на чем.

## 2. Крайние случаи — обязательный список

**Время**
- [ ] Матч 22:00 и 02:00 попадают в один игровой день.
- [ ] Матч 09:00 попадает в следующий день.
- [ ] Полночь, конец месяца, конец года.
- [ ] Браузер в другом часовом поясе — время всё равно МСК.

**Предикты**
- [ ] Ответ после лока не сохраняется.
- [ ] Частичные ответы: A < 0.8·Q → кубика нет.
- [ ] Q = 0 → день закрывается без наград и без ошибок.
- [ ] Отменённый матч уходит из Q и не портит точность.
- [ ] Чужие ответы не видны до лока (проверить через прямой запрос к API, не только UI).

**Кубики и резолв**
- [ ] Двойной вызов `rpc_resolve_matchday` не дублирует награды.
- [ ] Пересчёт дня корректно отзывает и заново выдаёт кубики.
- [ ] Игрок с 0 верных ответов получает бронзу (при участии ≥ 80%).
- [ ] Точный счёт даёт ровно один бонусный золотой.
- [ ] Кубики копятся и не сгорают между днями.

**Броски и механики**
- [ ] Двойной клик по кнопке броска не двигает дважды.
- [ ] Перезагрузка в середине VAR не даёт новый бросок.
- [ ] Незавершённый выбор блокирует только этого игрока.
- [ ] Ожидание второго участника не блокирует остальных.
- [ ] Щитки отменяют Офсайд и Жёлтую карточку, но не VAR.
- [ ] Жёлтая карточка поглощает Трибуны, но не уже висящие.
- [ ] Контратака не запускает событие новой клетки.
- [ ] Откат не уводит ниже 1.
- [ ] Брошенный VAR/Тактика через 24 часа закрывается безопасной веткой автоматически.
- [ ] Игрок на клетке 80 не может бросать и получает `PLAYER_FINISHED`.
- [ ] Пересчёт дня, где кубик уже потрачен, отклоняется с понятным сообщением.
- [ ] Утешительный d2 выдаётся не больше 2 раз за сезон.

**Данные**
- [ ] Провайдер вернул 500 → страницы работают на кэше.
- [ ] Квота исчерпана → синк деградирует, игра не падает.
- [ ] Дублирующийся матч не создаёт вторую запись.

### Дымовая проверка до подключения БД

Пока нет ключей Supabase, игра гоняется в демо-режиме (`lib/demo/snapshot.ts`). Минимальный ручной прогон перед релизом:

- [ ] Все маршруты открываются без ошибок консоли и без hydration mismatch: `/`, `/matches`, `/predictions`, `/ratings`, `/effects`, `/rules`, `/participants`, `/admin`, `/login`.
- [ ] Бросок кубика: персонаж двигается, в ленте появляются бросок и событие, счётчик кубиков уменьшается.
- [ ] Событие «Голевая передача»: список получателей, выбор партнёра, шаг +1, запись в ленте.
- [ ] Событие «VAR»: варианты «Принять −1» и «Оспорить», после выбора модалка закрывается.
- [ ] Событие «Раздевалка»: при негативе предлагает снять его, без негатива — шаг +1.
- [ ] Событие «Тактическая схема»: модалка появляется на следующем броске, «−1 / Оставить / +1» меняют итог.
- [ ] `/predictions`: прогресс участия, выбранные варианты, бонусный точный счёт.
- [ ] `/participants` и `/ratings`: 6 участников, кубики и эффекты совпадают с картой.
- [x] Мобильная ширина: 320×568, 375×720, 768×720 и 667×375 (альбомная) — шапка в две строки, табы с иконками, нет горизонтального скролла, кубики не перекрывают ленту; при высоте ≤ 560 px лента скрывается. Проверено через same-origin iframe-стенд, потому что браузерный инструмент не меняет вьюпорт.

Случайное выпадение кубиков в демо не воспроизводится один-в-один: событие ищется либо повторным броском на нужную клетку, либо временным сдвигом стартовой позиции в `lib/demo/snapshot.ts` (потом вернуть).

## 3. Playwright-сценарии релиза

1. `login.spec.ts` — вход игроком, вход админом, вход зрителем, неверный пароль.
2. `predictions.spec.ts` — ответить на 3 вопроса, проверить прогресс, проверить, что после лока форма закрыта.
3. `roll.spec.ts` — админ выдаёт кубик, игрок бросает, персонаж двигается, событие открывается.
4. `event.spec.ts` — VAR: выбрать «оспорить», увидеть результат, убедиться, что повторный заход не даёт новый бросок.
5. `matchday.spec.ts` — админ закрывает день, кубики появились, повторное закрытие не меняет результат.
6. `spectator.spec.ts` — зритель не видит кнопку броска, прямой POST отклоняется.

## 4. Деплой

### 4.1 Supabase

1. Создать проект (регион — ближайший к игрокам, EU).
2. `supabase link`, `supabase db push` — миграции.
3. Включить RLS на всех таблицах (`alter table ... enable row level security`), проверить политики запросом от анонима и от игрока.
4. Создать 6 пользователей + админа, заполнить `profiles` с ролями.
5. Загрузить `app_config` (пороги, очки, веса механик).
6. Настроить pg_cron (на free-тарифе Supabase `pg_cron` + `pg_net` доступны):

```sql
select cron.schedule('sync-fixtures', '0 */3 * * *', $$
  select net.http_post(
    url := 'https://<app>.vercel.app/api/cron/sync-fixtures',
    headers := jsonb_build_object('Authorization', 'Bearer <CRON_SECRET>')
  );
$$);

select cron.schedule('close-matchday', '*/15 * * * *', $$
  select net.http_post(
    url := 'https://<app>.vercel.app/api/cron/close-matchday',
    headers := jsonb_build_object('Authorization', 'Bearer <CRON_SECRET>')
  );
$$);

select cron.schedule('expire-pending', '*/15 * * * *', $$
  select net.http_post(
    url := 'https://<app>.vercel.app/api/cron/expire-pending',
    headers := jsonb_build_object('Authorization', 'Bearer <CRON_SECRET>')
  );
$$);
```

`sync-live` в v1 не нужен: счёт обновляет тот же `sync-fixtures` (окно −1…+4 игровых дня), а статусы дня и резолв ведёт `close-matchday`.

7. Проверить, что cron реально сработал: строки в `sync_runs` появились, у дня меняется статус, у брошенного ожидания через 24 часа появляется запись «судья решил за него».
8. Ручной прогон без планировщика: `curl -H "Authorization: Bearer <CRON_SECRET>" https://<app>.vercel.app/api/cron/expire-pending`. Без секрета — 401.

### 4.2 Vercel

1. Импорт репозитория, фреймворк Next.js.
2. Переменные окружения — из `01-architecture.md`, раздел 8; фактические имена — в `.env.example`. Минимум для боевого режима: `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `DATABASE_URL`, `FOOTBALL_DATA_TOKEN`, `CRON_SECRET`, `SEED_PASSWORD` (только для первого сида).
3. `npm run build` локально до пуша.
4. Домен: свой или `*.vercel.app`. Проверить доступность из РФ (мобильный интернет + проводной).
5. Расписание держим в `pg_cron` Supabase: на Vercel Hobby Cron ограничен одним запуском в сутки, а синку нужно чаще. Роуты `/api/cron/*` работают и от Vercel Cron, если тариф позволяет.
6. Если Vercel недоступен — резервный вариант Cloudflare Pages + тот же Supabase; код не меняется, меняется только хостинг.

### 4.3 Доступность из РФ

- Все внешние вызовы идут с сервера, поэтому блокировки на клиенте не влияют на данные.
- Если `*.supabase.co` тормозит — подключить кастомный домен через Cloudflare (proxy on) и прописать его в `NEXT_PUBLIC_SUPABASE_URL`.
- Проверить: вход, карта, звук, матчи — на телефоне в мобильной сети.

## 6. После запуска

**Первые 48 часов:** смотреть `sync_runs` (ошибки, квоты), `audit_log` (кто что правил), логи Vercel. Не деплоить новые фичи, только фиксы.

**Первая неделя:** собрать обратную связь по балансу (слишком жёсткие ловушки, скучные клетки), подкрутить `app_config` без релиза.

**Вторая неделя:** арт-проход — заменить временный фон на финальный, добавить анимации, которых не хватило.

**Дальше:** механики 11–18, затем карточки.

## 7. Откат

- Деплой: Vercel → Deployments → Promote предыдущего.
- БД: миграции только вперёд, каждая — идемпотентная. Разрушающие изменения (drop column) — отдельным релизом через неделю после того, как код перестал её использовать.
- Пересчёт дня: всегда через `rpc_recalculate_matchday` с причиной, никогда руками в SQL-редакторе.
