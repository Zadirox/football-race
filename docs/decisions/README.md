# Реестр решений (docs/decisions)

Эта папка — часть файловой памяти проекта для **новых и будущих согласованных** архитектурных/продуктовых/процессных решений (ADR-подобные записи).

## Как это связано с существующей документацией

- **`docs/DECISIONS.md`** — канонический подробный документ обязательных уточнений **D1–D13** (имеет приоритет над `docs/01`–`07` там, где они молчат или противоречат; см. его заголовок). Он сохраняется на месте, чтобы не ломать существующие ссылки и исторический контекст. Новые значимые долгосрочные решения фиксируются здесь (в `docs/decisions/`) и при необходимости индексируются из этого файла.
- **`docs/01-architecture.md`** — подробное описание архитектуры/схемы (исторически сложившийся документ). Компактная актуальная карта — в **`docs/ARCHITECTURE.md`**.
- **`docs/PROJECT_TRACKER.md`** — расширенный живой трекер (планы, долги, история сессий, бэклог). Краткое текущее рабочее состояние — в **`docs/WORKING_STATE.md`**.
- Точка входа и правила работы агента — **`AGENTS.md`** (корень).

Не создавайте параллельные «источники истины» для одного и того же решения: при появлении новой записи здесь указывайте связи с `docs/DECISIONS.md`, трекером, кодом и тестами.

## Шаблон записи

Скопируйте и заполните. Не придумывайте даты принятия, альтернативы, обоснования и ответы пользователя; неизвестное помечайте явно.

```md
# NNNN — Название решения

- **Статус:** предложено / принято / заменено / отменено
- **Согласование:** ожидается / подтверждено пользователем / явно делегировано пользователем / исторически не установлено
- **Дата фиксации:** YYYY-MM-DD
- **Дата принятия:** YYYY-MM-DD или «неизвестна» / «не применимо»
- **Статус реализации:** не начата / в работе / частично реализована / реализована / отменена / неизвестно

## Контекст и ограничения
- Что известно и какие ограничения влияют на выбор.

## Рассмотренные варианты (если известны)
- A. …
- B. …
- (Если варианты не рассматривались/не известны — указать это.)

## Рекомендация агента (если была)
- Вариант, причина. (Если не было — «не давалась». Не приравнивать к согласию.)

## Выбранное решение
- Что именно выбрано.

## Основание согласования и его границы
- Кто/когда/в каком объёме подтвердил; что делегировано; чего решение не покрывает.

## Причины выбора
- Зафиксированные причины (только подтверждённые).

## Последствия и компромиссы
- Плюсы, минусы, риски, влияние на код/данные/эксплуатацию.

## Связанные файлы и тесты
- Пути к реализации, миграциям, тестам (если есть).

## Источники и неизвестные детали
- Откуда взята информация (код, доки, обсуждение). Что не установлено.

## История замены
- Какое решение заменяет / каким заменено (если применимо).
```

## Правила качества

- Различайте **предложенный вариант**, **рекомендацию агента**, **согласованное пользователем решение** и **фактически реализованное решение**.
- Наличие реализации **не доказывает** согласование пользователем.
- Если решение ожидает ответа: статус согласования — «ожидается», в тексте явно указать **«Ожидает согласования. Реализация не разрешена»** (для соответствующего объёма).
- Заменённые решения помечайте как заменённые, не удаляя историю.
- Не записывайте секреты, токены, пароли, персональные данные и значения из `.env`.
