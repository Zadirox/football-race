# Доводка фронта к релизу 12 ноября — дизайн

Статус: на утверждении.
Дата: 11 ноября 2026.
Основание: `docs/03-map-and-art.md`, `docs/05-ui-roles-admin.md`, решения D1–D12, ответы в чате 11.11.

## 1. Задача

Каркас игры готов: карта, броски, события, предикты, рейтинги, админка, БД-слой. Не хватает «жизни» и краёв: карточки клетки, анимации хода, состояний экранов, мобильной полировки, глубины админки, финального арта.

Порядок работ (утверждён):

1. Клетки: карточка при наведении/тапе, флейворы обычных клеток, иконки механик.
2. Движение и звук: анимация броска, пошаговая ходьба, появление модалок и ленты.
3. Состояния: онбординг, `loading`/`error`/`not-found`, пустые состояния, вид зрителя.
4. Мобильная полировка (390×844).
5. Админка глубже.
6. Арт карты и иконок.

Каждый пункт сдаётся отдельно: тесты, `typecheck`, проверка в браузере.

## 2. Карточка клетки

### 2.1 Что видит игрок

Карточка — «пропуск на стадион». Тёмная панель, цветная полоса типа сверху, крупный номер, круглая иконка-штамп, название, одна строка смысла, тонкая перфорация между блоками.

Содержимое по типам клеток:

| Тип | Бейдж | Заголовок | Строка |
|---|---|---|---|
| Обычная | **Обычная клетка** (серый чип) | флейвор, напр. «Тики-така» | шутка, напр. «Три паса назад — и вперёд» |
| Событие | полярность: «Позитив» / «Негатив» / «Ловушка» / «Нейтрально» | название механики | `tagline` из каталога + строка «Сработает, когда встанешь» |
| Старт | «Старт» | «Старт» | «Отсюда все начинают сезон» |
| Финиш | «Финиш» | «Финиш» | «Кубок. Первый дошедший забирает сезон по дистанции» |

У обычной клетки **всегда** есть явный бейдж «Обычная клетка»; флейвор-название стоит рядом и ничего не меняет в правилах. Зоны карты в карточку **не выводим** до появления финального арта.

Полное описание механики остаётся на `/effects`; в карточке — только короткий эффект.

### 2.2 Поведение

- Мышь: наведение на маркер открывает карточку через 90 мс; уход закрывает.
- Клавиатура: фокус на маркере открывает, `Escape` закрывает, `blur` закрывает.
- Телефон: тап открывает закреплённую карточку, повторный тап по той же клетке или тап мимо закрывает.
- Карта не блокируется: карточка `pointer-events: none`, можно водить по клеткам и сравнивать.
- Драг и зум закрывают карточку; клик после драга не открывает её (`wasDrag()` из `usePanZoom`).
- Одновременно открыта одна карточка.

### 2.3 Где живёт и как позиционируется

Сейчас тултип лежит внутри `.map-canvas`, масштабируется вместе с картой и компенсирует зум через `--inv-scale`. У краёв он обрезается. Меняем:

- карточка рендерится порталом в `document.body`, координаты — экранные (`position: fixed`);
- якорь — `getBoundingClientRect()` маркера в момент открытия и при скролле/ресайзе;
- позиция считается чистой функцией `placeCard(anchor, card, viewport)`:

```ts
type Rect = { left: number; top: number; width: number; height: number };
type Placement = { left: number; top: number; side: 'top' | 'bottom'; arrowX: number };

placeCard(anchor: Rect, card: { width: number; height: number },
          viewport: { width: number; height: number }, gap = 14): Placement
```

Правила: по умолчанию сверху; если сверху не влезает — снизу; по горизонтали прижимается к краям с отступом 12 px; `arrowX` остаётся внутри карточки. Ширина `min(320px, 100vw − 24px)`, мобильная высота ограничена и скроллится только текст.

### 2.4 Данные флейворов

Новый файл `lib/game/cell-flavor.ts`:

```ts
export type PlainFlavor = { title: string; line: string };
export const PLAIN_FLAVORS: readonly PlainFlavor[]; // 40 штук, порядок = порядок пути
export function flavorMap(plainCells: number[]): Map<number, PlainFlavor>;
export function flavorFor(index: number): PlainFlavor;
```

`flavorMap` берёт обычные клетки по возрастанию номера и раздаёт флейворы по порядку. В текущей раскладке обычных клеток 38, два названия остаются запасными — это нормально и покрыто тестом. Старт и финиш флейворов не получают.

Список названий — утверждённый в чате (40 строк, от «Турникет и шаурма» до «Интервью после матча»).

### 2.5 Иконки механик

- Файлы: `public/art/mechanics/01.png` … `10.png`, 512×512, прозрачный фон, одна стилистика (см. `public/art/mechanics/README.md`).
- Компонент `components/map/MechanicArt.tsx`: `<img>` с `onError`, при отсутствии файла рисует SVG-заглушку в палитре игры.
- Соответствие «код механики → файл» — по `code` из `lib/game/catalog.ts`; замена картинки не требует правок кода.
- Обычные клетки получают нейтральную иконку-штамп (футбольный мяч/указатель), старт и финиш — свои.

### 2.6 Доступность

- Маркеры — `<button>` с `aria-label` («Клетка 27, Тики-така, обычная клетка»).
- Карточка `role="tooltip"`, связана с маркером через `aria-describedby` при открытии.
- Контраст текста ≥ 4.5:1, бейдж дублирует цвет словом.
- `prefers-reduced-motion`: карточка появляется без масштабирования.

## 3. Маркеры клеток

Форма остаётся круглой, меняются детали:

- номер крупнее и контрастнее, внутреннее кольцо по полярности;
- у событийной клетки — маленькая точка-иконка под номером, у обычной её нет;
- наведение даёт лаймовый ореол, текущая клетка игрока пульсирует как сейчас;
- пройденные клетки приглушены, финиш крупнее и золотой;
- размеры не зависят от зума (`--inv-scale` сохраняется).

## 4. Движение и звук

### 4.1 Бросок

1. Нажатие «Бросить» → кубик в лотке трясётся 700 мс, грани меняются каждые 70 мс.
2. Останавливается на выпавшем значении, короткая вспышка.
3. Персонаж идёт по клеткам: 220 мс на клетку, шаг — подскок токена + `play('step')`.
4. Приземление: `play('land')`, затем эффект клетки и модалка/тост.

### 4.2 Ходьба

- В `GameHud` появляется `displayPos` на игрока; при расхождении с `position` из снимка проигрывается очередь шагов.
- Модификаторы (контратака, офсайд, тактика, передача) идут той же анимацией, но быстрее: 140 мс на клетку.
- Ход ограничен 1..80; на финише — звук `reward` и золотая вспышка.
- Пока идёт ход, кнопка броска заблокирована.

### 4.3 Интерфейс

- Лента: новые записи въезжают справа с задержкой 40 мс друг за другом.
- Тосты: слайд снизу, автоскрытие 4 с, пауза по наведению.
- Модалки: затемнение 160 мс, панель scale 0.96 → 1.
- Страницы: короткий fade-in контента (150 мс), без «прыжков» layout.
- Звук по умолчанию выключен; включение — в шапке. Новые названия не вводим, используем существующие 10 из `lib/audio.ts`.

## 5. Состояния и онбординг

- `app/(game)/loading.tsx` — скелет карты и панелей.
- `app/(game)/error.tsx` — «Матч прерван», кнопка «Попробовать снова» (`reset`).
- `app/not-found.tsx` — 404 в стиле игры со ссылкой на карту.
- Онбординг при первом заходе: 3 шага (брось кубик → иди по клетке → отвечай на предикты), кнопки «Дальше» и «Пропустить», флаг `fg.onboarded.v1`; повторно открывается из «Правил».
- Пустые состояния: нет матчей, нет вопросов, нет участников, нет ленты — по одной строке и действию.
- Зритель и гость: плашка «Ты смотришь: играет основной состав», лоток кубиков неактивен с подсказкой, предикты только для чтения. Гость видит кнопку «Войти».

## 6. Мобильная полировка (390×844)

- Шапка в две строки: логотип + таймер, ниже табы с горизонтальным скроллом.
- Лоток кубиков — нижний док с учётом `safe-area-inset-bottom`; лента — кнопка с индикатором непрочитанного.
- Карточка клетки — ширина `100vw − 24px`, не выше 55% экрана.
- Таблицы рейтингов и участников на <640 px превращаются в карточки-строки.
- Проверка на 390×844 и 360×740: нет горизонтального скролла, ничего не перекрывает кнопку броска.

## 7. Админка глубже

Добавляем в `/admin`:

1. Правка матча: счёт, статус, минута — с валидацией и записью в активность.
2. Выдача кубиков: игрок, тир, количество, причина.
3. Ожидания: список `pending` всех игроков и принудительное закрытие.
4. Роли: игрок ↔ зритель ↔ админ, с запретом снять последнего админа.

Все действия — server actions в `lib/actions/admin.ts`: zod-схема, проверка админа, аудит-запись. В демо-режиме кнопки показывают тост «Нужна база».

## 8. Арт

- Фон: `public/art/map/map-night.webp`, 4096×2048, ≤ 1.2 МБ. `MapScene` рендерит `<img>` поверх процедурного SVG; при ошибке загрузки остаётся SVG.
- Иконки механик: `public/art/mechanics/01–10.png`, 512×512.
- `public/art/mechanics/README.md`: промпты, имена, размеры, негативный промпт, палитра.
- Зоны пути (вход, база, чаша, тоннель, фан-зона, финиш) остаются разметкой для арта; в интерфейс вернутся после фона.

Критерии приёмки:

- наведение/тап открывают карточку, у краёв она разворачивается и не обрезается;
- у каждой обычной клетки виден бейдж «Обычная клетка» и своё название;
- иконка механики грузится из файла, без файла — заглушка;
- бросок анимирован, персонаж идёт по клеткам, звук работает после включения;
- есть `loading`, `error`, `404`, онбординг и вид зрителя;
- на 390×844 ничего не ломается;
- админ может править матч, выдавать кубики, закрывать ожидания и менять роли;
- `npm run test:run`, `npm run typecheck`, `npm run build` зелёные.
