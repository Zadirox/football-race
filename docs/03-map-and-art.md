# 03. Карта: арт-дирекшн, слои, анимации, взаимодействие

## 1. Принцип

Карта — это не canvas-игра и не тайловая сетка. Это **одна большая рисованная изометрия + отдельные анимированные слои + DOM-маркеры поверх**. Ровно так сделано на референсе: фон — цельная иллюстрация, номера клеток — позиционированные элементы, анимации — отдельные спрайты.

Почему так: качество картинки определяется иллюстрацией, а не кодом; анимации остаются дешёвыми; маркеры и тултипы живут в обычном DOM и не требуют рендер-движка.

## 2. Размер и геометрия

| Параметр | Значение |
|---|---|
| Итоговый фон | 4096 × 2048 px, PNG/WebP, 2:1 |
| Проекция | изометрия 2:1 (диметрия, 30°), без перспективы |
| Пропорции экрана | на десктопе карта занимает весь viewport, скейлится по ширине |
| Зум | 0.6× – 1.6×, старт 1.0× (вписано по ширине) |
| Координаты клеток | нормализованные `x`, `y` в диапазоне 0..1 относительно фона |
| Сетка пути | 80 точек, змейка по сцене с 4–6 «поворотами» |

Маркер клетки: `left: x*100%`, `top: y*100%` внутри слоя `map-canvas`. При зуме масштабируется весь слой целиком (`transform: scale()`), поэтому координаты не пересчитываются.

## 3. Композиция сцены

Слева направо, по пути игрока:

1. **Трибуна и вход (клетки 1–12)** — поздняя осень: мокрый асфальт, первый снег пятнами, жёлтая листва, клубный магазин, турникеты.
2. **Тренировочная база (клетки 13–26)** — разминочные манекены, мячи в сетке, беговая дорожка, парковка автобуса команды.
3. **Стадионная чаша (клетки 27–48)** — главный объект: прожекторы, трибуны с crowd-текстурой, табло с бегущей строкой, флаги.
4. **Тоннель и раздевалка (клетки 49–60)** — коридор со светом из проёма, шкафчики, доска тактики.
5. **Фан-зона и ярмарка (клетки 61–72)** — ларьки, карусель, снежные фигуры, гирлянды, каток.
6. **Финиш (клетки 73–80)** — пьедестал с кубком, фейерверк, прожекторы в небо.

Визуальная граница сезонов: **клетки 1–16 — поздняя осень** (20%), **17–80 — зима** (80%). Переход — не резкая линия, а «снег пошёл сильнее»: пятна снега сгущаются к середине сцены.

## 5. Слои

```
<div class="map-viewport">              // overflow hidden, pointer events
  <div class="map-canvas" style="transform: translate(x,y) scale(z)">
    <img class="layer layer-sky" />      // небо, дальний город
    <img class="layer layer-ground" />   // земля, снег, газон
    <img class="layer layer-buildings" />// стадион, база, ларьки
    <img class="layer layer-path" />     // дорожки и сам маршрут (SVG)
    <div class="layer layer-sprites">    // анимированные спрайты (абсолютные div/img)
    <canvas class="layer layer-snow">    // частицы снега
    <div class="layer layer-markers">    // 80 маркеров клеток
    <div class="layer layer-players">    // 6 персонажей
  </div>
</div>
```

Требования:
- все слои — один размер и одна система координат;
- `layer-path` — SVG с `viewBox="0 0 4096 2048"`, ломаная через 80 точек, `stroke-dasharray` для «пунктира», как на референсе;
- `layer-snow` — canvas с 120–200 частицами, `requestAnimationFrame`, останавливается при `IntersectionObserver` вне экрана и при `prefers-reduced-motion`;
- спрайты — PNG с прозрачностью, не спрайт-лист, чтобы не плодить атласы на старте.

## 6. Генерация арта нейросетью

### 6.1 Общие требования к промпту (обязательно во всех генерациях)

- `isometric 2:1 dimetric projection, 30 degree angle, no perspective, orthographic`
- `night winter football stadium campus, first snow, warm floodlights, cozy atmosphere`
- `hand-painted stylized illustration, soft shading, clean shapes, muted teal-slate palette with warm amber light`
- `no text, no letters, no numbers, no UI, no people, no characters, no logos, no watermark`
- `consistent lighting from top-left`

### 6.2 Как генерировать, чтобы сцена не «поехала»

Генерировать одну сцену 4096×2048 за раз нельзя — модель потеряет детали и пропорции. Рабочая схема:

1. Сгенерировать **3 горизонтальные полосы** 1024×1024 с перекрытием 15%: `left`, `center`, `right`. Каждая — самостоятельная сцена, но с одним описанием стиля.
2. Для полосы `center` использовать первую как `image reference` (в GPT-Image / Midjourney `--sref`), чтобы палитра и толщина линий совпали.
3. Склеить вручную/скриптом, шов замазать в редакторе или «залечить» повторной генерацией узкой полосы-перехода.
4. Финальный фон прогнать через upscale до 4096×2048.
5. Проверить: линия горизонта одна, направление света одно, снег одного цвета.

Если шов не сходится за 30 минут — не героизировать, взять более простую композицию (меньше объектов, крупнее формы). Плоская чистая изометрия выглядит лучше, чем склеенный Франкенштейн.

### 6.4 Временный арт (если дедлайн горит)

Если 12 ноября арт не готов — использовать процедурную изометрию из простых форм (плоские платформы, снег, силуэты трибун) в той же палитре. Плохо нарисованная, но цельная карта лучше, чем склеенная каша. Арт-фон меняется одним файлом, без правок кода.

## 7. Анимации

| Элемент | Техника | Параметры |
|---|---|---|
| Снег | canvas-частицы | 150 шт., разная скорость и размер, лёгкий ветер |
| Прожекторы | PNG-слой + `mix-blend-mode: screen` + пульсация `opacity` | 4–6 с, дыхание 8% |
| Дым | спрайт + CSS `filter: blur(2px)`, дрейф вверх | 12 с, бесконечно |
| Гирлянды | `filter: drop-shadow` + мерцание по `animation-delay` | 2.5 c |
| Флаги | `transform: skewX()` туда-обратно | 3 с |
| Табло | бегущая строка текста, CSS `translateX` | 20 с, контент из `activity_log` |
| Трибуны | лёгкое «дыхание» яркости + редкие вспышки | 6 с |
| Персонаж | `translateY` покачивание 2 px + шаг по пути | 1.8 с |
| Активная клетка | пульс `box-shadow` | 1.6 с |
| Бросок кубика | CSS 3D rotation 0.9 с, затем приземление | Motion |
| Награда | вспышка + искры | 0.6 с |
| Смена погоды | `opacity` между слоями | 1.2 с |

Правила:
- анимируется только `transform` и `opacity` (GPU), никаких `top/left/width`;
- одновременно живых CSS-анимаций не больше 25;
- всё амбиентное выключается при `prefers-reduced-motion: reduce`;
- `animation-play-state: paused` когда вкладка не активна (`visibilitychange`).

## 8. Панорамирование и зум

```
pointerdown → захват (cursor: grabbing)
pointermove → translate3d(dx, dy), без transition
pointerup   → инерция: velocity * 220, затухание 0.92 за кадр
wheel       → зум к курсору: scale 0.6..1.6, шаг 0.08
двойной клик → зум 1.0 / 1.4
клавиши ← → ↑ ↓ → сдвиг на 120 px
кнопка «Домой» → сброс к старту
```

Ограничения:
- карту нельзя утащить целиком за экран: минимум 25% площади всегда видно;
- если карта меньше viewport, она центрируется и таскание отключается;
- таскание не выделяет текст (`user-select: none`);
- клик по маркеру не должен срабатывать как начало драга (порог 6 px).

## 9. Маркеры клеток

| Состояние | Вид |
|---|---|
| обычная | круг 26 px, фон `#2B3946`, белая цифра |
| событийная | круг с цветной обводкой по типу (позитив — лайм, негатив — красный, нейтрал — синий, ловушка — оранжевый) |
| активная (куда можно попасть) | пульсирующая обводка, лёгкое свечение |
| текущая позиция игрока | маркер персонажа стоит на клетке |
| пройденная | приглушена (60% opacity) |
| финиш | иконка кубка |

Тултип (как на референсе): тёмная карточка с крупным номером, бейджем типа («Обычная клетка», «Тематическая клетка», «Ловушка»), названием и одной строкой описания. Появляется на hover/фокус, у краёв экрана разворачивается в другую сторону. На тач — по тапу.

Доступность: маркеры — `<button>` с `aria-label="Клетка 17, ловушка, Офсайд"`, навигация стрелками по пути, `:focus-visible` видимый.

## 10. Персонажи

- 6 спрайтов, примерно 64×96 px, нарисованы в том же стиле, что фон.
- Стоят на своей клетке со смещением, чтобы не перекрываться: если двое на одной клетке, разносить по кругу радиусом 18 px.
- Клик по персонажу → мини-профиль: аватар, ник, позиция, кубики, очки, точность, активные эффекты, последнее действие.
- При перемещении — идти по точкам пути, а не по прямой: интерполяция по ломаной, 220 мс на клетку, 4 клетки = ~0.9 с.
- При событии — реплика в бабле («Офсайд! Судья поднял флажок»).

## 11. Звук

`public/audio/`, формат `.webm` (opus) + `.mp3` фолбэк. Всё через Howler.

| Файл | Когда |
|---|---|
| `ambient-night.webm` | фон карты, тихий стадион, -22 dB |
| `ambient-crowd.webm` | трибуны, реагирует на события |
| `ui-hover`, `ui-click` | интерфейс |
| `dice-roll`, `dice-land` | бросок |
| `step-1..3` | шаги персонажа |
| `event-positive`, `event-negative`, `event-neutral` | событие |
| `whistle-ref`, `var-buzz` | конкретные механики |
| `reward`, `coin` | награда |
| `pack-open`, `card-reveal` | фаза 2, заглушки уже сейчас |

Правила:
- звук по умолчанию **включён**, но тихо (амбиент -22 dB, эффекты -10 dB);
- кнопка mute в шапке, состояние в `localStorage` + профиль;
- амбиент стартует только после первого действия пользователя (политика браузеров);
- все звуки предзагружаются через Howler `preload`, без задержки на первом событии.

## 12. Производительность

Бюджет на главный экран: LCP < 2.5 с на десктопе, 60 fps при панорамировании.

- фон — WebP, качество 82, плюс `blur` placeholder;
- спрайты — отдельные файлы по 20–80 КБ, грузятся после первого рендера;
- никаких `box-shadow` на десятках элементов, только на активных;
- `will-change: transform` только на `map-canvas`, снимается после инерции;
- снег отключается на слабых машинах: если средний FPS < 45 за 3 секунды — уменьшить частицы вдвое.
