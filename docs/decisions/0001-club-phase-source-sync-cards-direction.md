## Контекст и ограничения
- После Лиги наций планируется клубный этап (ЛЧ/ЛЕ/ЛК + whitelist матчей топ-лиг для 54 клубов), 1 календарная дата = 1 матчдэй, ~4 вопроса/матч, узкое окно синка, те же механики при отдельном клубном паке/карточках с матчингом по клубу.
- Текущая реализация: football-data.org (`/v4/matches`, без детальной статистики в нормализации) + sstats.net (сейчас UNL, list+detail, извлечение corners/cards/possession/shots), sync с бюджетом/частичным прогрессом, окно `[-1,+4]`.
- Ограничения: cron/таймауты, идемпотентность, зависимость от покрытия/лимитов внешних API, необходимость статистики для вопросов/резолва, отсутствие в БД клубных card set/pack/cards (см. `docs/ARCHITECTURE.md`, `docs/PROJECT_TRACKER.md`, `docs/WORKING_STATE.md`).

## Рассмотренные варианты (источник данных, 2B)
- **Вариант 1:** football-data.org основной (расписание/счёт), статистика отдельным путём.
- **Вариант 2:** sstats.net основной (расписание + статистика) для нужных клубных соревнований.
- **Вариант 3 (гибрид):** football-data.org для discovery/расписания по лигам/соревнованиям, где доступен; sstats.net для детальной статистики и/или для турниров, где FD слаб/не даёт нужных данных.
- Сравнение и чеклист верификации представлены в диалоге (шаг 2B, 2026-11-20). Выполнена probe-верификация (FD/sstats): FD даёт CL+PL/PD/BL1/SA/FL1/DED/PPL (EL/ECL недоступны; часть нужных дом. лиг отсутствует в доступных comps), sstats покрывает UCL/UEL/UECL и все выявленные дом. лиги whitelist 54 и предоставляет детстаты в detail.

## Рекомендация агента (если была)
- Изначально рекомендован **Вариант 3** поэтапно. После верификации пользователем выбран **Вариант B (sstats primary для всех целевых соревнований)**; рекомендация варианта 3 как предпочтительного не принята в финальной конфигурации источников (зафиксирован выбор B).

## Выбранное решение (подтверждённые рамки)
- **2C.1 Whitelist 54 клубов:** **A — конфиг в репозитории**, формат **A (TypeScript-модуль)** (подтверждено 2026-11-20). Состав 54 клубов подтверждён пользователем (2026-11-20). `lib/data/club-phase.ts`: whitelist 54 клуба (`slug`, `nameRu`, `country`, `leagueKey`, `inCardPool`, `sstatsAliases`) — **подтверждён и заполнен** (алиасы по probe sstats Year=2026). Исходно описан набор из 19 соревнований; **sync-scope уточнён в Этапе 3 (Y4, подтверждено 2026-11-21)** — см. 2C.3. Финальные правила матчинга/дедупа при реализации sync — при необходимости уточняются отдельно.
- **2C.2 Окно синка:** **A — `[-1, +1]`** (вчера, сегодня, завтра).
- **2C.3 Источники и соревнования (уточнено 2026-11-20, Y4/Этап 3 подтверждено 2026-11-21):** выбран **Вариант B: sstats primary** для расписания/статуса/счёта и детальной статистики (FD не используется / резерв). **Приоритет при конфликте/канонизация:** sstats приоритетнее. **Scope:** **UCL — все матчи**; **UEL/UECL — только матчи с участием клубов из whitelist 54** (A2); **домашние лиги (включённые в sync) — только матчи с участием клубов из whitelist 54**. **sstats Year:** **Year=2026** per-competition. **Этап 3:** **3.1=A** (даты с national/UNL in-scope — national-only, club на этих датах не прикрепляются), **3.2=A** (канонический `league_code` per comp + `sstatsLeagueId` в `raw`), **3.3=A** (все included comps, best-effort, euro-cups priority, идемпотентно). **Y4 included comps (9, sync):** `CL`(2), `EL`(3), `ECL`(848), `PL`(39), `PD`(140), `BL1`(78), `SA`(135), `FL1`(61), `SLTR`(203). **Удалены из sync comps:** Eredivisie(88), Primeira(94), Eliteserien(103), Jupiler Pro BE(144), Bundesliga AT(218), Super League GR(197), Czech Liga(345), Super Liga SK(332), UPL(333), Premyer Liqa AZ(419) — **клубы из этих лиг остаются в whitelist** для UEL/UECL. ## Причины выбора
- Зафиксировано в диалоге: необходимость детальной статистики для вопросов/резолва и покрытие UCL/UEL/UECL + всех нужных дом. лиг whitelist 54 в одном источнике (sstats), подтверждённое probe-верификацией; узкое окно `[-1,+1]`; MVP-рамка клубных паков с матчингом по клубу в коллекции/составах; запись в БД — после согласования модели.

## Последствия и компромиссы
- Единый источник (sstats) упрощает модель статистики и приоритетов, но создаёт зависимость от одного провайдера и его лимитов/структуры; требуется контроль бюджета запросов (list+detail) и устойчивость парсинга. FD остаётся резервом (отдельное решение).
- Конфиг whitelist в репо упрощает MVP, но изменения требуют деплоя. Окно `[-1,+1]` повышает шанс получить поздние коррекции ценой небольшого роста объёма.
- Y4 (9 comps) снижает объём/нагрузку sync, но часть дом. лиг whitelist-клубов не синкается напрямую (клубы сохранены в whitelist для UEL/UECL) — важно для покрытия матчей и ожиданий.
- 3.1=A исключает club-матчи на даты с national in-scope (без mixed матчдэев/миграций) — упрощает контур грантов, но может оставлять club-матчи вне обработки в такие даты.
- Продуктовые правила 2C.4 и данные/схема 2C.5b/c реализованы в рамках согласий, но Stage 4 (линейки/поведение), edge-cases матчинга и эксплуатационная валидация остаются открытыми.
