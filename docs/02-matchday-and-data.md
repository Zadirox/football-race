# 02. Игровой день, данные и авто-резолв

Это самый важный документ. Ошибка здесь = неверные кубики, неверные места на карте и обиженные друзья.

## 1. Время

### 1.1 Правило нарезки

Игровой день D = **с 09:00:00 МСК дня D до 08:59:59 МСК дня D+1**.

```ts
// lib/time.ts
export const MSK = 'Europe/Moscow';
export const DAY_CUT_HOUR = 9;

/** Игровой день, к которому относится матч. */
export function gameDateOf(kickoffUtc: Date): string {
  const local = toZoned(kickoffUtc, MSK);        // 'YYYY-MM-DD HH:mm' в МСК
  const hour = Number(local.slice(11, 13));
  return hour >= DAY_CUT_HOUR
    ? local.slice(0, 10)                        // тот же день
    : shiftDate(local.slice(0, 10), -1);        // ночной матч → вчерашний игровой день
}
```

Проверки, обязательные в `tests/unit/time.test.ts`:
- 21:00 МСК понедельника → понедельник;
- 00:30 МСК вторника → понедельник;
- 02:00 МСК вторника → понедельник;
- 08:59 МСК вторника → понедельник;
- 09:00 МСК вторника → вторник;
- 23:45 МСК воскресенья → воскресенье;
- переход через границу месяца и года;
- Москва не переходит на летнее время, но функция не должна на это полагаться.

### 1.2 Хранение и вывод

- В БД — только `timestamptz` в UTC.
- На фронт отдаём ISO UTC + готовую строку `МСК` (сервер форматирует, чтобы не зависеть от часового пояса браузера).
- В UI всегда подпись: `22:00 МСК`, `Сегодня`, `Завтра`.

### 1.3 Дедлайны

- `questions.locks_at` = `matches.kickoff_utc` конкретного матча. Лок поштучный, не на весь день.
- `locks_at` — **кэш**. Источник истины — `matches.kickoff_utc`: проверка приёма ответа сравнивает с ним, а синк обновляет `locks_at` триггером при изменении времени (`DECISIONS D10`). Матч перенесли раньше — приём ответов закрылся сразу.
- `matchdays.closes_at` = 08:59:59 МСК следующего календарного дня.
- День закрывается не по таймеру, а когда **все матчи дня** получили финальный статус (`FT`, `PST`, `CANC`, `ABD`). Таймер — только страховка: если данные не пришли за 3 часа после `closes_at`, день закрывается по тому, что есть, а необработанные матчи помечаются `void`.

## 2. Источники данных

Используем два провайдера с разными ролями.

| Провайдер | Роль | Лимит (проверить в кабинете) | Что берём |
|---|---|---|---|
| football-data.org | основной: фикстуры, результаты, статусы, счёт | бесплатный тариф, порядка 10 запросов/мин | матчи 8 нужных турниров |
| RapidAPI (Football API из личного кабинета) | обогащение: логотипы, доп. рынки, статистика | у бесплатных тарифов жёсткий лимит (у похожих — 100 запросов/мес) | по необходимости, только не для polling |

Правило: **если провайдер не отдал — система не падает, а работает на кэше.**

Нужные турниры (маппинг в `lib/data/leagues.ts`):

```
PL  — АПЛ
PD  — Ла Лига
SA  — Серия А
BL1 — Бундеслига
FL1 — Лига 1
CL  — Лига чемпионов
UNL — Лига наций
EC  — Чемпионат Европы / WC — Чемпионат мира
```

Всё остальное игнорируется на этапе нормализации. Никакой РПЛ, никаких вторых дивизионов.

### 2.1 Синк фикстур

`GET /api/cron/sync-fixtures`, запускается pg_cron раз в 3 часа + вручную из админки.

```
окно: [сегодня − 1 день, сегодня + 4 дня] по МСК
для каждого турнира из списка:
  запрос фикстур
  upsert в matches по (provider, external_id)
  маппинг статуса: SCHEDULED/TIMED→NS, IN_PLAY/PAUSED→LIVE/HT, FINISHED→FT,
                   POSTPONED→PST, CANCELLED/SUSPENDED→CANC, AWARDED→FT
  назначение игрового дня через gameDateOf(kickoff)
  создать matchday (status='scheduled') если его ещё нет
  связать матч с днём через matchday_matches
записать sync_runs (provider, endpoint, status, duration, error)
```

Защита от дублей: `unique(matches.provider, matches.external_id)`. Матч никогда не пересоздаётся, только обновляется.

### 2.2 Синк лайва

`GET /api/cron/sync-live`, pg_cron каждые 60 секунд, но с гейтом:

```
if нет матчей в статусе LIVE и нет матчей со стартом в ближайшие 10 минут:
   выход без запросов (0 квоты)
иначе:
   один запрос на турнир, где сейчас есть активные матчи
```

Итог: в спокойный день — 0–10 запросов, в игровой вечер — до 200–300. Это укладывается в 10 req/min, если не опрашивать все 8 турниров каждую минуту.

Обновляем: `status`, `minute`, `home_score`, `away_score`. Логотипы и названия — при первом появлении матча.

### 2.3 Деградация

- Провайдер вернул 429 → пауза, экспоненциальный бэкофф (2с, 8с, 32с), запись в `sync_runs`.
- 3 подряд ошибки → бейдж «Данные обновлены 14:32» в шапке, игра продолжает работать.
- Квота RapidAPI исчерпана → провайдер отключается флагом в `app_config`, синк идёт только через football-data.org.
- Никогда не вызываем футбольный API из клиента и никогда не показываем пользователю сырой ответ провайдера.

## 3. Предикты

### 3.1 Состав дня

- Админ выбирает 3–5 матчей на игровой день (из тех, что вообще есть). Автоподбор предлагает топ по «весу» турнира + балансу (не больше 2 матчей одного турнира).
- На каждый матч — 3–5 обычных вопросов + 1 бонусный вопрос «точный счёт».
- Итого в типичный день: 12–25 обычных вопросов + 3–5 бонусных.
- У всех участников **один и тот же** набор вопросов.

### 3.2 Генерация вопросов

Бесплатные тарифы провайдеров не отдают линию, поэтому вопросы строятся из **детерминированных шаблонов с фиксированными порогами** (см. `DECISIONS D1`). Никаких коэффициентов в v1.

| Шаблон | kind | Пример | Правильный ответ вычисляется как |
|---|---|---|---|
| Победа в матче | `choice` | «Кто победит: Арсенал / Ничья / Челси» | сравнение финального счёта |
| Тотал 2.5 | `yes_no` | «В матче будет больше 2.5 голов» | `home + away > 2.5` |
| Обе забьют | `yes_no` | «Обе команды забьют» | `home > 0 && away > 0` |
| Тотал одной команды | `yes_no` | «Арсенал забьёт 2+» | `home >= 2` |
| Гол в первом тайме | `yes_no` | «Будет гол до перерыва» | `ht_home + ht_away > 0` |
| Точный счёт | `exact_score` | «Угадай точный счёт» | точное совпадение, `is_bonus = true` |

Правила генерации:
- на один матч — 3–4 обычных вопроса + 1 бонусный «точный счёт»;
- не больше 2 вопросов одного шаблона **на матч** (не на день);
- итого по дню: 4–5 матчей × 3–4 = **12–20 обычных вопросов**;
- варианты ответа детерминированы и хранятся в `questions.options`, чтобы старые ответы не «переехали» при смене формулировки;
- формулировка фиксируется в момент создания. Меняешь вопрос — создаётся новый, старый уходит в `void`;
- для «гола в первом тайме» провайдер обязан отдавать счёт первого тайма. Если не отдаёт — вопрос не создаётся, а не угадывается по финальному счёту.

Ручной режим: админ создаёт/редактирует вопросы в админке до старта первого матча дня. После первого лока — только `void` + новый вопрос.

### 3.3 Ответы

- Игрок отвечает на каждый вопрос отдельно. Можно ответить частично.
- Дедлайн — `locks_at` (старт своего матча). Просрочил — ответ не принимается, вопрос считается неотвеченным.
- Изменение ответа до лока разрешено, после — нет (проверка на сервере, не в UI).
- Чужие ответы скрыты до лока. После лока видны всем — это часть веселья.

## 4. Резолв дня

### 4.1 Когда запускается

Переходы статусов (`DECISIONS D4`):

| Из | В | Триггер |
|---|---|---|
| `scheduled` | `locked` | наступил `kickoff_utc` первого матча дня |
| `locked` | `live` | хотя бы один матч в `LIVE` или `HT` |
| `locked`/`live` | `resolving` | все матчи дня в финальном статусе |
| `resolving` | `closed` | успешный резолв |
| `resolving` | `live` | резолв упал, матч ещё не завершён |

1. Cron каждые 5 минут переводит статусы и находит дни в `resolving`.
2. Или админ нажимает «Закрыть день» вручную.

Финальные статусы: `FT`, `PST`, `CANC`, `ABD`.

### 4.2 Алгоритм

```
rpc_resolve_matchday(p_matchday):
  begin
    select ... for update matchdays where id = p and resolved_at is null
    if not found: вернуть существующий результат (идемпотентно)

    -- 1. Резолв вопросов
    for each question in matchday:
       if question.match.status in (PST, CANC, ABD):
          question.status = 'void'; correct_option = null
       else:
          question.correct_option = evaluate(question, match)
          question.status = 'resolved'

    -- 2. Q = число не-void обычных вопросов
    q_total = count(questions where status='resolved' and is_bonus=false)

    -- 3. По каждому игроку сезона
    for each player:
       answered = count(answers on resolved non-bonus questions)
       correct  = count(answers where is_correct = true, non-bonus)
       accuracy = answered / q_total                       -- для порога участия

       if accuracy < 0.80:
           dice = none
       else if correct * 3 >= q_total * 2:
           dice = gold   (d6)
       else if correct * 3 >= q_total:
           dice = silver (d4)
       else:
           dice = bronze (d3)

       bonus = exists(answers where is_correct and question.is_bonus)
       if bonus and accuracy >= 0.80:
           выдать ещё один gold (d6), source='exact_score'

       начислить очки: +10 за каждый верный обычный,
                       +40 за верный точный счёт

    -- 4. Закрыть день
    matchdays.status = 'closed'; resolved_at = now(); q_total = q_total
    -- 5. Лента
    activity_log: сводка по каждому игроку
  commit
```

### 4.3 Математика кубика — канон

- `Q` — число действительных обычных вопросов дня.
- `A` — сколько обычных вопросов игрок ответил.
- `C` — сколько из них верных.
- Порог участия: `A / Q >= 0.8`. Иначе кубика нет вообще.
- `3C >= 2Q` → золото (d6).
- `3C >= Q` → серебро (d4).
- иначе → бронза (d3), включая `C = 0`.
- Точный счёт: `+1` золотой кубик, максимум один за день, только при выполненном пороге участия. Точный счёт не входит в `Q` и `C`.

Примеры (проверить юнит-тестами):

| Q | C | Результат |
|---|---|---|
| 20 | 0–6 | бронза |
| 20 | 7–13 | серебро |
| 20 | 14–20 | золото |
| 16 | 0–5 | бронза |
| 16 | 6–10 | серебро |
| 16 | 11–16 | золото |
| 12 | 0–3 | бронза |
| 12 | 4–7 | серебро |
| 12 | 8–12 | золото |
| 4 | 0–1 | бронза |
| 4 | 2 | серебро |
| 4 | 3–4 | золото |
| 3 | 1 | серебро (3·1 ≥ 3) |
| 3 | 2 | золото (6 ≥ 6) |
| 0 | — | кубиков нет, день «Отдых» |

Граничные правила: ровно 1/3 — серебро, ровно 2/3 — золото. Никаких `Math.round`, только целочисленные сравнения.

### 4.4 Идемпотентность

- `resolved_at` защищает от повторного резолва.
- Кубики выдаются через `insert ... on conflict do nothing` по уникальному индексу (см. `01-architecture.md`), поэтому двойной клик админа не даёт второй кубик.
- Очки — через `unique(season_id, profile_id, kind, ref_table, ref_id)` в `score_events`.
- Админский пересчёт (`rpc_recalculate_matchday`) разрешён **только если ни один кубик этого дня ещё не потрачен**; иначе возвращает `RECALC_BLOCKED_DICE_SPENT`, а админ правит последствия вручную (выдать/списать кубик, сдвинуть позицию) с записью в `audit_log` (`DECISIONS D3`).

### 4.5 Перенос и отмена

- Матч стал `PST` → вопрос `void`, исключён из `Q`. Никто не наказан, никто не получил кубик «за воздух».
- Матч перенесли на другой день, но он уже сыгран в рамках дня → результат фиксируется в том дне, где был вопрос. Пересчёт не переносит награды между днями.
- Матч отменён после резолва → админ запускает пересчёт, причина обязательна.

## 5. Пропущенный день

- Штрафа нет.
- **«Отложенный тур»**: за каждый пропущенный день (0 ответов при `Q >= 5`) при следующем действии игрока начисляется утешительный `d2` (тир `wood`), максимум **2 за сезон**, не сгорает, `source='catchup'`. Факт выдачи пишется в `catchup_grants(season_id, profile_id, granted_at)`, чтобы лимит не зависел от nullable `matchday_id` (`DECISIONS D9`).
- Пропуск не даёт очков и не влияет на рейтинг точности (иначе точность падала бы у всех, кто честно болеет).

## 6. Рейтинги

| Рейтинг | Формула | Тайбрейкер |
|---|---|---|
| Дистанция | `season_players.position` по убыванию | больше сумма бросков, потом раньше зарегистрирован |
| Очки | сумма `score_events.points` | больше верных предиктов |
| Точность | `correct_answers / answered_answers` за сезон, минимум 30 ответов для попадания в таблицу | больше ответов |

Точность считается только по обычным вопросам (бонусные не портят статистику).

## 7. Матчи на сайте

Вкладка «Матчи» показывает три блока:
1. **Сейчас** — идущие матчи со счётом и минутой.
2. **Далее** — ближайшие 3 дня по МСК, сгруппированные по игровым дням, с логотипами.
3. **Итоги** — последние завершённые.

Источник — только БД. Страница рендерится серверно, обновляется через Realtime-канал своего дня (или polling раз в 60 секунд, если Realtime отвалился).

## 8. Что проверить перед запуском

- [ ] Матч в 22:00 и матч в 02:00 попадают в один игровой день.
- [ ] Матч в 09:00 попадает в новый день.
- [ ] Перенесённый матч выкидывается из `Q`, кубики пересчитываются.
- [ ] Двойной вызов резолва не выдаёт второй кубик.
- [ ] Двойной клик по «Бросить» не двигает персонажа дважды.
- [ ] Игрок, ответивший на 1 вопрос из 20, не получает кубик.
- [ ] Точный счёт даёт ровно один бонусный кубик.
- [ ] Квота API не превышена в игровой вечер (проверить `sync_runs` после первого дня).
